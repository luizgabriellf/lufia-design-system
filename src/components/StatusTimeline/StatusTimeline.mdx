<Section id="overview">

A vertical, connected timeline of obligations or steps grouped into tracks. Each node has an icon, a state pill, an
optional timestamp or deadline, a hint, and an optional inline action.

<Canvas of={Stories.Default} />

### Usage

```tsx
import { StatusTimeline } from "@lufia/design-system/components/StatusTimeline";

<StatusTimeline
  tracks={[
    {
      id: "review",
      title: "Review",
      nodes: [
        {
          id: "n1",
          label: "Notify the team",
          state: "done",
          stateLabel: "Done",
          timestampLabel: formatted,
        },
      ],
    },
  ]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use; the package has none.

States: `needsTimestamp`, `pending`, `overdue`, `done`, `notApplicable`. Pass your own domain values straight through.

<Section id="accessibility">

### Accessibility

- Each track is a `<section>` with an `<h3>`; each node list is an ordered list, so order and count are announced.
- **State is named in words** through `stateLabel` in the pill; colour and icon are reinforcement only. Always pass a
  meaningful `stateLabel`.
- Overdue uses a solid fill, never a tint, so it cannot be read as pending. The danger fill uses a dedicated
  `on-solid` text token that passes AA in light and dark.
- Layout stays vertical at every width: no horizontal scrolling or truncated text at 320px.
- Actions are slots; keep them keyboard operable and labelled.
- In forced-colors mode the pill keeps a visible border.

</Section>

<Section id="guidelines">

### When to use

- Tracking dated obligations or a multi-party process where order and status both matter.

### When not to use

- A simple progress indicator (use `Stepper`) or an activity feed.

### Content guidelines

All text arrives formatted and localised (dates in the user's locale: `5 Nov 2026` vs `05/11/2026`). Avoid colour words
("red") in labels.
