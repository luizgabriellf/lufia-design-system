<Section id="overview">

The action row of a page: one primary action, a few secondary ones, and an overflow menu. It is meant for the `actions` slot
of `PageHeader`.

<Canvas of={Stories.InPageHeader} />

### Usage

```tsx
import { PageActions } from "@lufia/design-system/components/PageActions";

<PageActions
  moreLabel="More actions"
  primary={{ key: "new", label: "New report", onSelect: create }}
  secondary={[{ key: "share", label: "Share", onSelect: share }]}
  overflow={[{ key: "del", label: "Delete all", tone: "danger", onSelect: confirmDeleteAll }]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from your copy layer.

### Responsive behaviour

| Width        | Primary | Secondary actions   | Overflow menu button                       |
| ------------ | ------- | ------------------- | ------------------------------------------ |
| 48rem and up | Button  | Buttons             | Shown when `overflow` has items            |
| Below 48rem  | Button  | Moved into the menu | Always shown, with secondary then overflow |

The switch is pure CSS, so there is no flash on first paint. Secondary actions exist in both places; the menu entries are
flagged and hidden on wide screens, and keyboard navigation skips what is hidden.

Below 60rem the open menu is a bottom sheet over a backdrop that covers the viewport; see `MoreActions` for how to raise
its stacking order above an app's own fixed bar with `--lufia-overlay-z`.

### Collapse by container

`collapse="container"` makes the secondary actions follow the width of a host container instead of the page: below 50rem
they move into the menu, from 50rem they are buttons. The host (any ancestor) must declare `container-type: inline-size`;
the query uses the nearest one, and with none the secondary actions never collapse. There is no container name and no
threshold prop, because a container condition cannot read a variable. It is pure CSS, so there is no flash on first paint,
and it combines with `hideBelow` and `primaryPlacement`, which stay viewport rules. A popover is inside the container, so
the query reaches it. A sheet (viewport below 60rem) is portalled to the body and has left the container, so in this mode
it always lists the secondary actions.

```tsx
<div style={{ containerType: "inline-size" }}>
  <PageActions collapse="container" moreLabel="More actions" secondary={secondary} overflow={overflow} />
</div>
```

### Data attributes on actions

`attributes` on an action (`{ "data-tour": "share" }`) renders those `data-*` attributes on its button or link and, for a
secondary action, on its overflow menu item, so tours and tests can target one action without a label lookup.

<Canvas of={Stories.WithDataAttributes} />

### Hints for disabled actions

`hint` on an action (primary, secondary or a `MoreActions` item) is the native tooltip and the description of the control
(`aria-describedby` to a visually hidden copy). A disabled action with a hint is `aria-disabled` and stays focusable, with
activation ignored, so keyboard and screen reader users can reach the reason (the APG advice for disabled controls that
need an explanation). Without a hint a disabled button stays natively disabled.

<Canvas of={Stories.DisabledWithHint} />

### App shell integration

- `size="sm"` shrinks the buttons and the menu button for compact headers (default `"md"`).
- `hideBelow="medium"` hides the whole row below 60rem, in CSS.
- `primaryPlacement="external"` hides only the primary action below 60rem, for an app shell that renders it elsewhere (a
  floating bar); it stays inline on wide screens.
- The root carries `data-lufia-part="page-actions"`, `data-primary-placement` and `data-hide-below`, and passes `className`
  and any other attribute (such as `data-*`) through, so shell CSS and end-to-end tests can target it.

<Section id="accessibility">

### Keyboard

Buttons follow `Button`; the menu follows `MoreActions` (arrow keys, Home, End, typeahead, Escape). See both pages.

### Accessibility

- Every control is a native button or link, or the menu from `MoreActions`; the menu button is named by `moreLabel`.
- On narrow screens an action is reachable in the menu only, so keep labels meaningful out of context.
- A hinted disabled action is `aria-disabled`, not `disabled`, so it takes focus and announces its reason.
- The row does not wrap, so it never pushes content around when it collapses.

</Section>

<Section id="guidelines">

### When to use

- The actions that apply to the whole page: create, import, share, export.

### When not to use

- Actions on one row or card: use `IconButton` or `MoreActions` there.
- More than one primary action.
- Navigation between views: use `PeerNav`.

### Content guidelines

Verbs first, one to three words. Put the destructive action last in the menu and label it explicitly.
