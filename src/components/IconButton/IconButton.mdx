<Section id="overview">

A `Button` that shows only an icon. The accessible name is required by the types, and a tooltip comes with it.

<Canvas of={Stories.AllVariantsAndSizes} />

### Usage

```tsx
import { IconButton } from "@lufia/design-system/components/IconButton";

<IconButton icon={<SettingsIcon />} aria-label="Open settings" onClick={openSettings} />;
```

The string in the snippet is a plain literal. In your app it arrives through props from your copy layer. Omitting `aria-label`
is a type error.

### Toggle

Pass `aria-pressed` to make it a toggle. A pressed `ghost` or `secondary` button takes the accent subtle fill with the accent
border and text, which differs from rest and from hover, and a thicker `Highlight` border in forced-colors mode. Keep the
`aria-label` the same in both states: the state is `aria-pressed`, not a changed name.

<Canvas of={Stories.Pressed} />

### Tooltip

The tooltip is the package `Tooltip` behaviour, not a native `title` attribute: no `title` is rendered, so a browser tooltip
never shows a second time. It shows on mouse hover after a short delay and on keyboard focus, and goes away on Escape, blur and
scroll. Its text is `aria-label`; `title` overrides it (for a shortcut hint, say). `tooltipPlacement` picks the side (`top` by
default). `tooltip={false}` turns it off, for a button you wrap in your own `Tooltip`, or while a menu it opens is showing.
Your own `onPointerEnter`, `onPointerLeave`, `onFocus`, `onBlur` and `onKeyDown` still run. Tests that looked a button up by its
title should query by accessible name (`getByRole("button", { name })`).

### Large circular media control

`size="xl"` is 4rem and `shape="circle"` makes the box round with equal sides. Together they make a control over a poster or a
player. The icon is 1.75rem at `xl`; `--lufia-icon-button-icon-size` changes it. `xl` is an `IconButton` size: `Button` keeps
`sm`, `md` and `lg`. A theme can resize every icon-only box with `--lufia-icon-button-size`.

### Keyboard

| Key           | Action                                                                      |
| ------------- | --------------------------------------------------------------------------- |
| Tab           | Moves focus to the button and shows its tooltip (a disabled one is skipped) |
| Escape        | Hides the tooltip; focus stays                                              |
| Enter / Space | Activates a button; Enter activates a link                                  |

### Accessibility

- `aria-label` is the accessible name. The tooltip shows the same text, is `aria-hidden` and is never the name, so nothing is announced twice.
- The tooltip shows on keyboard focus and mouse hover, not on touch, which is why the name must not depend on it.
- The icon is hidden from assistive technology.
- The target is 2.5rem square at the default size (2rem at `sm`, 2.75rem on coarse pointers), above the WCAG 2.5.8 minimum.
- Focus ring, loading and forced-colors behaviour are those of `Button`.

### Do and don't

<IconButtonDoDont />

### When to use

- Compact, well-known actions where the icon is unambiguous: close, search, settings, overflow.
- Toolbars and table rows where a text label would not fit.

### When not to use

- Actions whose icon is not obvious. Use a `Button` with a label instead.
- The primary action of a view: it deserves a visible label.

### Content guidelines

Name the action, not the picture: "Open settings", not "Cog". Keep it to two or three words.
