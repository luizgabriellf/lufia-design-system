<Section id="overview">

A form field that holds a list of short text entries: one text input per entry, editable in place, an add row and a remove
button on each entry. The entries are submitted as one hidden text value.

<Canvas of={Stories.Default} />

### Usage

```tsx
import { ListField } from "@lufia/design-system/components/ListField";

<ListField
  name="responsibilities"
  label="Responsibilities"
  labels={{
    add: "Add",
    addInput: "New responsibility",
    remove: (index, text) => `Remove entry ${index}: ${text}`,
    entry: (index) => `Entry ${index}`,
    requiredMessage: "Add at least one entry.",
  }}
  defaultItems={["Inspect the site"]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use:
the package has no built-in language, so every string is in `labels`.

The field carries its own label, hint and error, like `RadioGroup`. Do not wrap it in a `FormField`.

</Section>

### The submitted value

With `name`, a hidden input submits `serialize(items)`. The default joins the entries with a line feed; pass `serialize` to
store them with your own delimiter. `sanitizeItem` cleans an entry when it is added and whenever the entries are read (trim,
collapse spaces); an entry that is empty after it is left out.

### Controlled and uncontrolled

Pass `defaultItems` and read the value from the form, or pass `items` and `onChange`. A controlled value that differs from
what the field holds replaces its rows, so a parent that refuses a change keeps its list.

<Canvas of={Stories.Controlled} />

### Required, and the pending draft

`required` means at least one entry. The add input carries `labels.requiredMessage` as its custom validity until there is
one, so the browser refuses the submission and shows it. Text typed in the add input is not part of the value until it is
added: call `commitDraft()` on the ref right before the form is submitted. It returns whether an entry was added, and the
hidden value is up to date when it returns.

<Canvas of={Stories.Required} />

### Including the draft

Pass `includeDraft` and the text still in the add input is part of the submitted value, exactly as if the add button had
been pressed: the hidden value is `serialize([...items, draft])` while the draft is not empty after `sanitizeItem` and
`maxItems` and `maxTotalLength` leave room for it. `onChange` is not called for it and the add input keeps its text, so
the person can still press add. With `required`, a valid draft satisfies the rule, so the form submits with only a draft
typed. It is off by default: without it a draft is ignored by both the value and `required`, and `commitDraft()` is the
way to add it before submitting.

<Canvas of={Stories.IncludeDraft} />

### Limits

`maxItems` (default 30) caps the number of entries, `itemMaxLength` each entry and `maxTotalLength` the length of the
serialized value. The add input stops accepting text at the room left, separators included, and adding is disabled when
there is none.

### Counter

`renderCount` receives `{ count, maxItems, length, maxTotalLength }` and returns the text of a counter ("2 of 5 entries").
It renders as secondary text under the hint and is part of the group's description, so a screen reader reads it after the
hint. `count` leaves out a pending draft. Nothing is rendered without it, and the package adds no wording.

### Accessibility

| Key / action           | Behaviour                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| Tab                    | Moves through the entries, their remove buttons, the add input and the add button.       |
| Enter in the add input | Adds the text as an entry. It never submits the surrounding form.                        |
| Enter in an entry      | Keeps the edit and moves focus to the add input. It never submits the form.              |
| Remove button          | Removes the entry and moves focus to the add input, so focus is never lost with the row. |

- The field is a `group` named by its label. Each entry input is named by `labels.entry(index)`, each remove button by `labels.remove(index, text)`.
- The label points at the add input, which takes the label as its name unless `labels.addInput` is set. Set it (for example "New hazard" under a group "Hazards" with an "Add" button) so the input and the button never share a name. The hint, the counter and the error describe the group.
- Rows enter with a rise and fade and leave with a fade, using only `opacity` and `transform`; under `prefers-reduced-motion` they appear and disappear at once. A leaving row is `inert`.
- Remove buttons are at least 32px tall and grow to the 44px touch target on touch screens and phone widths.
- No live region: the list is the content, and focus stays on a control the person is using.

<Section id="guidelines">

### When to use

- A list of short values the person writes themselves: tasks, tags, phone numbers, keywords.
- Storing the list as one text column, with your own delimiter.

### When not to use

- Long or formatted entries: use `Textarea`.
- Choosing from known options: use `Combobox` or a set of checkboxes.
- Entries with several fields each: build a form for the row.

### Content guidelines

Say what one entry is in the label and what the delimiter or limit is in the hint. Name the remove button after the entry
it removes ("Remove entry 2: Inspect the site"), not just "Remove".
