An overflow menu: a button that opens a list of less frequent actions. It follows the WAI-ARIA menu button pattern.

<Canvas of={Stories.Open} />

### Usage

```tsx
import { MoreActions } from "@lufia/design-system/components/MoreActions";

<MoreActions
  label="More actions"
  items={[
    { key: "dup", label: "Duplicate", onSelect: duplicate },
    { key: "settings", label: "Settings", href: "/settings" },
    { key: "del", label: "Delete record", tone: "danger", onSelect: confirmDelete },
  ]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from your copy layer. Items with `href`
render as links through the `linkComponent` set on `LufiaProvider`.

### Popover placement

The open popover is portalled to `document.body` (or into the open modal the button sits in, so the modal's focus trap and
inert page do not lock it out) and placed with `position: fixed` from the button's box. An ancestor with `overflow: hidden`,
such as a card with rounded corners, cannot clip it. It lines up with `align`, flips to the other edge when it would run past
the viewport, opens upward when there is not enough room below and more above, scrolls inside when the list is taller than
the room it has, and follows the button on scroll (of any ancestor) and resize. Before the component has mounted (server
render, hydration) the menu renders in place. In `narrowOnlyScope="container"` the portalled menu reads the container's
width when it opens, and on resize, because it has left the container its `@container` query would reach.

### Sheet presentation

`presentation` chooses how the open menu is shown. `"popover"` (the default) hangs it from the button. `"sheet"` shows a
full-width sheet anchored to the bottom of the viewport. `"auto"` is a sheet below 60rem (the `medium` breakpoint) and a
popover from there up; `PageActions` uses it. The sheet is rendered in a portal on `document.body`, over a backdrop that
covers the whole viewport, with the page behind made `inert` and page scroll locked. Its height is capped at 70% of the
dynamic viewport (and 32.5rem); longer lists scroll inside it without scrolling the page. The bottom padding includes the
safe-area inset.

#### Stacking above an app's dock

The sheet sits at `--lufia-overlay-z`, which defaults to one above `--lufia-z-modal`. An app with a fixed dock or bar above
that layer sets the property on the root to a value above its own element, so the backdrop and sheet clear it:

```css
:root {
  --lufia-overlay-z: 1200; /* above the app's fixed bottom bar */
}
```

The sheet registers on the shared overlay stack (through `useFocusTrap`), so a `Modal` or another popup opened from it, and
`registerOverlayLayer`, order correctly: only the topmost layer reacts to Escape. Optional hooks: `--lufia-sheet-backdrop`,
`--lufia-sheet-max-block-size`, `--lufia-sheet-max-inline-size`.

### Open a dialog from a menu item

An action that needs a dialog or a form does not need the content inside the menu. Keep the state in the caller, render
the dialog next to `MoreActions`, and open it from `onSelect`. The dialog stays mounted after the menu closes because the
menu never owns it. `MoreActions` closes first and puts focus back on its button before `onSelect` runs (for a sheet, once
the sheet is gone), so a `Modal` opened by the action takes focus and returns it to that button when it closes.

```tsx
const [renaming, setRenaming] = useState(false);

<MoreActions label="More actions" items={[{ key: "rename", label: "Rename", onSelect: () => setRenaming(true) }]} />
<Modal open={renaming} onClose={() => setRenaming(false)} title="Rename record">
  <RenameForm />
</Modal>
```

A native `<dialog>` works the same way: call `showModal()` from `onSelect`. Several actions can share one dialog by
keeping which action was chosen in the caller's state.

### Data attributes and narrow-only scope

- `attributes` on an item (`{ "data-tour": "export" }`) renders those `data-*` attributes on its `menuitem` element, so an app
  can anchor a tour or a test to one item without a label lookup.
- `narrowOnlyScope="container"` makes `narrowOnly` items follow the width of the nearest ancestor with
  `container-type: inline-size` (below 50rem) instead of the page (below 48rem). A sheet leaves that container, so it always
  shows them. `PageActions` sets this from its `collapse` prop.

### Keyboard

| Key                        | Where   | Action                                                                  |
| -------------------------- | ------- | ----------------------------------------------------------------------- |
| Enter / Space / Down arrow | Trigger | Opens the menu and focuses the first item                               |
| Up arrow                   | Trigger | Opens the menu and focuses the last item                                |
| Down / Up arrow            | Menu    | Next / previous item, wrapping; disabled items are included             |
| Home / End                 | Menu    | First / last item                                                       |
| A letter or letters        | Menu    | Typeahead: jumps to the next item starting with them; resets after 0.5s |
| Enter / Space              | Item    | Activates the item, closes the menu, and returns focus to the trigger   |
| Escape                     | Menu    | Closes the menu and returns focus to the trigger                        |
| Tab                        | Menu    | Closes the menu, returns focus to the button, moves on from it          |
| Tab / Shift+Tab            | Sheet   | Next / previous item, wrapping: focus stays in the sheet                |

A press outside closes the menu. Escape and outside presses go through `useDismiss` and the shared layer stack, so inside a
dialog Escape closes the menu first and the dialog on the next press. The component adds no document listeners of its own.

In a sheet, Escape and a tap on the backdrop close it and focus returns to the button. The chosen action runs after the sheet
has closed, so a dialog it opens returns focus to the button when it closes.

### Accessibility

- The trigger is an `IconButton` named by `label`, with `aria-haspopup="menu"`, `aria-expanded` and `aria-controls`.
- The list is `role="menu"` with `role="menuitem"` entries; focus moves between items (roving focus) and returns to the
  trigger on close or selection.
- Disabled items are `aria-disabled`: they stay focusable and readable (APG) but cannot be activated.
- Choosing a link item also returns focus to the button. The popover flips to the other edge of the button when it would run past the viewport, and opens upward when there is no room below. With no items, no button is rendered.
- A destructive item (`tone="danger"`) is styled red, but its label must say what it does ("Delete record"), since colour
  never carries the meaning alone.
- A sheet traps focus, makes the page behind inert and restores focus to the button; the visible heading repeats the menu's
  name and is hidden from assistive technology. Under reduced motion it appears without the slide and fade.
- Items are at least 2.5rem tall, 3rem on narrow screens. The menu is limited to the viewport width and wraps long labels.
- In forced-colors mode the menu border is `CanvasText` and the focus ring `Highlight`. Under reduced motion the menu appears
  without the fade.

<Section id="guidelines">

### When to use

- Infrequent or secondary actions for a record, a row or a page, behind one button.
- Page actions that no longer fit on a narrow screen (`PageActions` does this for you).

### When not to use

- Navigation between pages: use `PeerNav` or the app shell.
- Two or three actions that fit: show them as buttons.
- Choosing a value (a select or combobox) or a form's submit.
- The only way to reach an important action. Keep the main action visible.

### Content guidelines

Items start with a verb and are one to three words. Put the destructive item last. Descriptions are optional and one short
phrase.
