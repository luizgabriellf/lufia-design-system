<Section id="overview">

A data table built from native table elements, styled with CSS only. It scrolls sideways with a shadow on each edge that
has more to see, sets its headers in small monospace capitals and, when its own width is under 40rem, becomes a list
of cards. It holds no state: sorting, filtering and paging stay with the app, which hands in the rows.

<Canvas of={Stories.Default} />

### Usage

```tsx
import {
  Table,
  TableHead,
  TableBody,
  TableFoot,
  TableRow,
  Th,
  Td,
} from "@lufia/design-system/components/Table";

<Table caption="Projects">
  <TableHead>
    <TableRow>
      <Th>Project</Th>
      <Th>Status</Th>
      <Th numeric>Budget</Th>
    </TableRow>
  </TableHead>
  <TableBody>
    <TableRow>
      <Td primary label="Project" href="/projects/1">
        Harbour redesign
      </Td>
      <Td label="Status">Active</Td>
      <Td label="Budget" numeric>
        12,400
      </Td>
    </TableRow>
  </TableBody>
</Table>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use; the package has none.

None of the parts has `"use client"`, so a table renders in a Server Component. `onActivate` passes a function, so a row that
uses it has to be written in a Client Component; `href` does not.

### Cards on narrow widths

`responsive="cards"` (the default) answers to the width of the table itself, not of the window, so a table in a narrow
column is a list of cards on a wide page. Under 40rem the header row is hidden visually and kept for assistive technology,
each row is a card, the `primary` cell is its title, every other cell shows its `label` before the value and an `actions`
cell wraps its buttons. There is no sideways scroll in that mode. Give every `Td` the same `label` as its column header.

Under 30rem of the table's width the label sits above the value, so the value has the whole card and a long label word is
not split inside the word; from 30rem the label sits beside the value. A `Badge` inside a card cell wraps its text instead
of being clipped by the value column, without `wrap` on every badge (the table sets `--lufia-badge-white-space: normal`
for its card cells).

#### Card layout controls

All of these apply in card mode only; table layout and `responsive="scroll"` ignore them.

- **Title first.** The `primary` cell is always the first line of the card, whatever its column. Cards are a flex column and
  the primary cell has a low CSS `order`. Trade-off: `order` changes the visual order only. Reading order and Tab order
  follow the markup, so keep the primary cell early in the markup when you can and treat `cardOrder` as a small move, not
  a reshuffle (WCAG 1.3.2 and 2.4.3).
- **`stretch` on `Td`.** By default the value of a labelled cell is start-aligned and as wide as its content, which keeps a
  `Badge` at its natural size. Block content that relies on stretching (a progress bar in a wrapper, a `flex: 1` child)
  would shrink to its minimum width, so set `stretch` on that cell: its value then takes the whole width. Existing badge
  and text cells are unchanged because it is opt-in.
- **`cardLayout="grid"` on `Table`.** Labelled cells sit in two columns of label-over-value pairs, so a nine-column row is
  a few lines, not a tall stack. Under 20rem of the table's width it falls back to one column. The title, the actions
  cell and cells without a `label` take the full width; give a wide value `cardSpan="full"` on its `Td`. Default is
  `stack`, one cell per line. A cell is half the row wide but never narrower than its content: a badge keeps its text on
  one line in this layout, so a long pill (a date, a status) takes a line of its own instead of wrapping onto two, while
  short pills and text still pair up. This needs no prop. A pill longer than the whole card still overflows; give that one
  `Badge wrap`, which opts it back in to wrapping.
- **`cardSlot="corner"` on `Td`.** The cell leaves the flow and is pinned to the card's top end corner (a drag handle or an
  overflow menu), so it adds no line of its own and a cell with no `label` leaves no gap. It uses logical properties and
  mirrors in right-to-left. The `primary` cell reserves room beside it (`--table-corner-reserve`, default 2rem, wide enough for
  a small icon button), so the title never runs under it; with no `primary` cell nothing reserves that room.
  In card mode the corner cell ignores an inline `width` (such as `style={{ width: "1%" }}`, used to keep the column narrow in
  table layout) and keeps the size of its content: a percentage would resolve against the card and squeeze it to a few
  pixels. The table layout keeps your width.
- **`wrap` and `abbr` on `Th` and `SortableTh`.** Two ways for a long header to take less width, so a wide table scrolls
  sideways less. `wrap` lets the text take two balanced lines, aligned to the bottom of the header row (the whole row
  aligns to the bottom, so one-line headers sit level with the last line). `abbr="Qty"` shows the short text and keeps
  the children as the full name: the full name is what assistive technology reads, the short text is hidden from it and
  carries the full name as a `title` tooltip (when the children are a string), the `<th>` gets the native `abbr`
  attribute, and the revealed header row of a card table shows the full name. Both are opt-in; a header without them
  behaves as before. They combine, and `SortableTh` accepts both.
- **`cardOrder` on `Td`.** A number, mapped to CSS `order` (lower first, default 0, `primary` before everything). Use a
  negative number on the `actions` cell to put it right under the title, a positive one to keep it last.
- **`hideInCards` on `Td` and `Th`.** For a column whose value is repeated in the card (a company name already in the title).
  The cell is hidden visually but kept in the accessibility tree, on purpose: removing it would leave the row with fewer
  cells than header cells and break the header association. It is read by assistive technology like any cell; if the value
  is truly redundant there, mark it `aria-hidden` yourself.

- **`cardColumns` on `Table`.** With `cardLayout="grid"`, `cardColumns={3}` (or `4`) puts that many labelled cells on a line
  of the card, for a comparison row: the title, then one value per option side by side. The default, `2`, is the layout
  above and leaves every existing table as it was. A pair is never narrower than its content: when the cells do not fit
  they wrap onto the next line, so a narrow card does not overflow. With 3 or 4 columns the one-column fallback under 20rem
  does not apply, that wrapping does the work instead; keep the values short (a price, a tick) or use `cardSpan="full"`
  for a long one. Use it on tables of up to four value columns.

<Canvas of={Stories.ComparisonCards} />

- **`emphasis` on `Th` and `Td`.** Highlights one column in table and card mode with a tinted background. Set it on the
  column's `Th` and on each of its `Td`s. The tint is a visual cue only: when it means something (a recommended plan), pass
  `emphasisLabel="Recommended"` on the `Th` and the cells, text from the app, which is added visually hidden after the
  content so assistive technology reads it too. Restyle it with `--lufia-table-emphasis-bg` (default the accent subtle
  background), `--lufia-table-emphasis-color` and `--lufia-table-emphasis-font-weight`, both inherited by default. In forced
  colours the tint is dropped and the cell is set bold.

### Clickable rows

Give one cell of the row `href` (a link through the `linkComponent` of `LufiaProvider`) or `onActivate` (a button). The
cell's content becomes that real control, and its click area is stretched over the whole row. The `<tr>` has no click
handler and no `role="button"`, so the row is announced once, as a link or a button named by the cell, and links keep
open in new tab, copy address and middle click. Buttons and links in other cells, such as an `actions` cell, sit above the
stretched area and do their own thing.

<Canvas of={Stories.ClickableRowsAsLinks} />

A row that cannot be opened right now takes `activateDisabled` on the same cell. The button form stays focusable with
`aria-disabled="true"`, the way `Button` and `Pagination` do, so focus is not lost; activation is ignored. The link form
is rendered without `href`, so it cannot be followed. Both read in the muted text colour and the row loses its hover.

### Inside a panel

`frame="flush"` drops the table's own border, radius and background, so the table sits edge to edge in a container that
already has a frame. The header rule and the row separators stay; in card mode each card keeps its own border.

<Canvas of={Stories.FlushInPanel} />

The scroll shadows are hidden by two covers that scroll with the content, painted with `--lufia-table-cover-bg` (default
`--lufia-table-bg`). Under `flush`, when the surface token is translucent or the table sits on a different colour, set
`--lufia-table-cover-bg` to an **opaque** colour equal to what is behind the table; a translucent cover cannot hide the
shadows and a band shows at both edges once the table overflows.

<Canvas of={Stories.FlushTranslucentSurface} />

**Idle covers.** When the table does not overflow, the covers and the shadows are not painted at all, so a translucent
surface shows no band at either edge even with no cover token. This uses a scroll-driven animation: the scroll timeline of a
container with nothing to scroll is inactive, so a constant keyframe that switches the covers on never applies. It needs
`animation-timeline` (Chromium 115 and later, Safari 26 and later; check current support for Firefox). Where it is missing
the rule is skipped and nothing changes from before: the covers and shadows are always painted, which is invisible on an
opaque surface and a band on a translucent one, so keep setting an opaque `--lufia-table-cover-bg` there. While the table
does overflow, a translucent surface still needs the opaque cover token, as above.

<Canvas of={Stories.FlushTranslucentIdle} />

### Typography, caption, alignment and colour hooks

For a table placed in prose, a container can restyle the table without redefining global tokens. Every hook falls back to
today's value, so nothing changes until one is set. Set them to a concrete value: a custom property set to the keyword
`inherit` does not inherit the font, so name a token such as `var(--lufia-font-family-body)`.

| Hook                                                                                                   | Applies to                                                | Default                                                         |
| ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- | --------------------------------------------------------------- |
| `--lufia-table-header-font-family`, `-font-size`, `-font-weight`, `-letter-spacing`, `-text-transform` | column headers and, in card mode, the labels              | mono, 2xs, medium, 0.06em, uppercase (labels: weight inherited) |
| `--lufia-table-caption-color`, `-font-size`, `-font-weight`                                            | the visible caption (`showCaption`)                       | default text, inherited, semibold                               |
| `--lufia-table-cell-vertical-align`                                                                    | body cells and row headers                                | `middle`                                                        |
| `--lufia-table-cell-color`                                                                             | body cells that are not `primary`, in table and card mode | inherited text colour                                           |
| `--lufia-table-primary-color`                                                                          | the `primary` cell                                        | default text colour                                             |

`captionTone="muted"` sets the visible caption in the muted text colour; `--lufia-table-caption-color` overrides either tone.
The colour hooks apply with no specificity, so a colour a consumer sets on a cell or its content still wins. Set
`--lufia-table-cell-vertical-align: top` for rows of several lines; the controls of a `Td actions` cell still share one centre
line, and a header row with `Th wrap` keeps its bottom alignment. To keep a long header on one line or let it wrap, see `Th wrap`
and `abbr` in the card controls notes above. Pick colours that keep WCAG AA contrast on the surface: the package's contrast
gate checks its own tokens, not what a container sets.

### Actions column

In table layout the `Td actions` column is as wide as its buttons and its content sits at the end edge (the right edge in
left-to-right text, the left in right-to-left), however few columns there are, and it never wraps, so three or four text
buttons can force a sideways scroll at mid widths. The controls share one centre line, so an icon button and a text-only
button do not drift apart. Card mode is unchanged.

<Canvas of={Stories.FewColumnsActions} />

Set `wrap` on `Td actions` to let the controls flow onto a second line instead (end-aligned, with a gap, each button
keeping its label on one line). With room, all the controls sit on one line; only when the table would otherwise
overflow do they wrap. The `Th actions` header needs no prop: the column follows its cells. Prefer that for two or three short actions; with more than two text actions prefer one
overflow menu in the cell, which keeps every row one line tall.

### Numeric cells

In table layout a `numeric` cell never wraps, so an ISO date or date-time is not broken at its hyphens when the table is
tight; the table scrolls (or turns into cards) instead. In card mode the value wraps as usual.

<Canvas of={Stories.TightNumericColumns} />

### Naming the row control, descriptions and extra links

`activateLabel` is the `aria-label` of the generated link or button ("Open details of Harbour redesign") and
`activateDescribedBy` its `aria-describedby`. `description` adds a muted, regular-weight line under the cell's content; it
is inside the control, so without `activateLabel` it is part of the control's name. `after` renders content in the same
cell but outside the control, above the stretched click area: a second link or a mailto next to the name stays a
separate, focusable control, never nested in the row's link. It sits on its own line under the content. Keep the visible
text inside `activateLabel` (WCAG 2.5.3, label in name): "Open details of Harbour redesign" contains the visible "Harbour
redesign"; a label that drops a visible `description` does not.

<Canvas of={Stories.NamedRowControl} />

### Row header

Set `rowHeader` on the `Td` that names the row, usually the first. It renders `<th scope="row">` (`role="rowheader"`), so
assistive technology reads it as the header of every other cell in the row, and it keeps the look of a body cell: the
monospace capitals belong to column headers only. Every other `Td` prop works on it, and with `primary` it is the title of
the card. A bare `<Th scope="row">` in a body row gets the same body-cell look, but has no `primary`, `label` or `description`; use
`Td rowHeader` for those.

A highlighted row is a `className` or `style` on `TableRow`, and a cell can hold any inline content, such as a bar: the
table adds nothing for either.

### Total row

`TableFoot` renders `<tfoot>` and goes after `TableBody`. Its rows are ordinary `TableRow`s: start with a `Td rowHeader`
("Total", a real `<th scope="row">`) and follow with `Td numeric` cells. Foot rows read stronger than body rows (semibold,
a rule above the first one) and have no hover; do not give them `href` or `onActivate`. In `responsive="cards"` mode the
foot becomes one last summary card, with a stronger border and the raised surface, and each cell shows its `label` and
value like a body card, so give foot cells with a value the same `label` as the column (an empty cell without a `label` shows nothing). In
`scroll` mode it is a plain table foot.

### Row state

`TableRow` takes `selected` (`aria-selected` and a selected background) and `current` (`aria-current="true"` and an accent on
the start edge). The app owns the state; there are no checkboxes.

<Canvas of={Stories.RowState} />

### Grouped rows

One `Table` can hold several `TableBody`s. Start each with a group header row, `<TableRow group>` holding a single
`<Th scope="colgroup" colSpan={n}>` that spans every column; `colSpan` and `rowSpan` pass through on `Td` and `Th`, and a
`Th scope="rowgroup"` is announced as a row header. In card mode the group header is a full-width heading above its cards,
not a card.

### Refs and inline styles on rows

`TableRow`, `TableHead`, `TableBody`, `TableFoot`, `Th` and `Td` take `ref` and `style` like the elements they render, so a
sortable-list library that needs the row element, an inline `transform` and `transition` and its own `data-*` and `aria-*`
attributes can drive them.

<Canvas of={Stories.RowWithRefAndStyle} />

### Focus room under sticky bars

`--lufia-table-row-scroll-margin` (default `0`) is applied as `scroll-margin-block` on the row control and on focusable
controls in actions cells. Set it to the height of a sticky header or fixed bottom bar and the browser keeps that much
room around the control it scrolls into view. In card mode the browser still scrolls only the control, not the whole
card: a scroll margin in CSS cannot know the card's height, and the package ships no script for it. Size the hook for
the card if you need more room.

<Canvas of={Stories.ScrollMargin} />

Parts: `TableHead`, `TableBody` and `TableFoot` take their native element's props. `TableRow` adds `selected` and `current`. `Th` adds
`numeric` (default `scope="col"`) and `actions` with a required `label`, for the header of the actions column: its text is
visually hidden, so no `aria-label` on an empty header. `Td` adds `label`, `numeric`, `primary`, `actions`, `wrap` (with `actions`), `href`,
`onActivate`, `activateLabel`, `activateDescribedBy`, `description` and `after`. `TableEmpty` takes the props of
`EmptyState` plus `colSpan`, with `title` optional: without it `children` is the one-line message. `Table` adds `frame` and `captionTone`.

Theming hooks: `--lufia-table-bg`, `--lufia-table-border`, `--lufia-table-scroll-shadow`, `--lufia-table-cover-bg` (opaque
colour of the shadow covers; default `--lufia-table-bg`), `--lufia-table-row-hover`, `--lufia-table-row-scroll-margin`, and the typography, caption, alignment and colour hooks listed under "Typography, caption, alignment and colour hooks".

### Keyboard and accessibility

| Key                        | Action                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| Tab / Shift+Tab            | Moves through the scroll region, each row's link or button, and the controls in its cells |
| Enter                      | Follows a row's link, or presses its button                                               |
| Space                      | Presses a row's button (a link answers to Enter only)                                     |
| Arrow keys (on the region) | Scroll the table sideways when it is focused                                              |

- The `<caption>` names the table and the scroll region around it. The region is focusable, so a keyboard user can scroll a
  table that has nothing focusable in the hidden columns (WCAG 2.1.1). It costs one tab stop; give each table on a page its own
  caption, since a region is a landmark and landmarks need distinct names.
- Exactly one of `caption`, `aria-label` and `aria-labelledby` is required (the type enforces it). With `aria-label` or
  `aria-labelledby` no `<caption>` is rendered, and the same name is put on the table and on the scroll region. Use them for
  a table generated from free content (rendered markdown) or one a heading already names. There is no unnamed form: WAI-ARIA
  does not strictly require a name on a simple data table, but this one sits in a focusable scrolling region, which is a
  landmark, and an unnamed focusable region fails axe and is announced as just "region".
- Card mode changes `display` on table parts, which some browsers answer by dropping the table semantics. Explicit `table`,
  `rowgroup`, `row`, `columnheader`, `rowheader` and `cell` roles keep them, and the hidden header row keeps naming every
  column. The visible column label in a card is drawn by CSS with an empty text alternative, so it is not read twice.
- A sortable header in card mode is still a control. While one has keyboard focus the header row shows, so no one is on
  something they cannot see.
- A clickable row is a real `<a>` or `<button>` in one cell, stretched over the row, not a `<tr tabindex="0" role="button">`.
  That keeps one tab stop and one announcement per row, lets controls inside the row be reached on their own (a button
  inside a `role="button"` row is a nested control), and keeps link behaviour. A consequence: text in a clickable row
  cannot be selected with the mouse.
- A row control can be named with `activateLabel` ("Open details of ..."), so a screen reader hears the action and the
  subject, not the cell's text. Content in `after` is a separate control after it in the tab order.
- `selected` is `aria-selected` on the row and `current` is `aria-current="true"`; neither adds a control or a keyboard
  behaviour, and a colour or accent alone is not the only cue for the app to rely on: pair state with text where it matters.
- The focus ring surrounds the whole row. Reduced motion needs nothing: the table has no animation. In forced colours the row
  hover gets an outline, and the scroll shadows, which are backgrounds, are not drawn.
- Interactive controls in a row reach at least 24 by 24 CSS pixels through their own components; the stretched control
  covers the row.

<Section id="guidelines">

### When to use

- Records with several attributes that people compare, scan or open.

### When not to use

- A layout (use CSS grid) or a short list of one value per line (use `DetailList` or a list).
- Data that needs cell editing, selection, a virtual window of many thousand rows or a column model. This is the
  presentation of a table, not a data grid.

### Content guidelines

`caption` says what the rows are: "Projects", "Invoices for March". Keep a `label` identical to its column header. Put the
row's identity in the `primary` cell and make it the one with `href` or `onActivate`; keep the actions to a few short
buttons that wrap well.
