<Section id="overview">

A dialog that blocks the page behind it until the person answers or dismisses it. Portaled to `document.body`, with focus
containment, scroll lock, an inert background and an enter/exit motion.

### Usage

```tsx
import { Modal } from "@lufia/design-system/components/Modal";

<Modal
  open={open}
  onClose={() => setOpen(false)}
  title="Edit project"
  description="Rename the project or change who can see it."
  footer={
    <>
      <button onClick={() => setOpen(false)}>Cancel</button>
      <button onClick={save}>Save changes</button>
    </>
  }
>
  <form>...</form>
</Modal>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use.
The modal is controlled: it never closes itself, it calls `onClose`, and you decide what happens.

### Sizes

`sm` (26 rem) for short questions, `md` (35 rem, default) for forms, `lg` (48 rem) and `xl` (60 rem) for dense content.
Below 600 px every size becomes a sheet anchored to the bottom of the screen that rises into view.

<Canvas of={Stories.Large} story={{ inline: false, height: "30rem" }} />

### Dismissal policy

Three ways out, each one switchable: the close button (`hideCloseButton`), Escape (`closeOnEscape`) and a click on the
backdrop (`closeOnOutsideClick`). For a form with unsaved input, turn the last two off and let the footer buttons decide.

<Canvas of={Stories.StrictDismissal} story={{ inline: false, height: "30rem" }} />

A click only closes when the press **began** on the backdrop. Selecting text inside the dialog and releasing the mouse
outside it does not.

### Busy

While `busy`, the dialog has `aria-busy="true"`, the close button is disabled and every dismissal is refused. Use it while
an action that cannot be aborted is in flight. Re-enable it when the request settles; do not leave it `busy` forever.

### Theming hooks

Set these `--lufia-modal-*` custom properties in your theme, or on the panel through `style` or `className`, to reshape
the modal without forking it. All are optional and the defaults are unchanged.

| Property                                                                                     | Controls                                          |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `--lufia-modal-radius`                                                                       | Panel corner radius                               |
| `--lufia-modal-header-padding`, `--lufia-modal-body-padding`, `--lufia-modal-footer-padding` | Padding of each part (a `padding` shorthand)      |
| `--lufia-modal-title-size`                                                                   | Title font size                                   |
| `--lufia-modal-close-size`                                                                   | Close button width and height                     |
| `--lufia-modal-backdrop`                                                                     | Backdrop colour                                   |
| `--lufia-modal-sheet-offset`, `--lufia-modal-sheet-radius`                                   | Phone sheet gap to the screen edge, corner radius |
| `--lufia-modal-scroll-shadow`                                                                | Edge shadow colour of `scrollShadow`              |

`size` also takes any CSS length (`size="62rem"`). `sheetPlacement="top"` hangs the phone sheet from the offset instead of
rising from the bottom, `titleWrap="ellipsis"` keeps the title on one line, and `scrollShadow` scrolls the body between a
fixed header and footer with an edge shadow.

### Part hooks and class names

Every part carries a stable `data-lufia-part` attribute: `layer`, `backdrop`, `frame`, `panel`, `header`, `title`,
`description`, `body`, `footer` and `close`. They do not change between releases, so an app can target them in CSS and in test
selectors while it migrates. `classNames` adds your own class to a part (`classNames={{ panel, header, body, footer, close,
backdrop }}`, plus `layer`, `frame`, `title` and `description`); the root `className` still goes to the panel. In
`renderAs="dialog"` mode there is no `layer`, `frame` or `backdrop` element: the backdrop is the native `::backdrop`.

<Canvas of={Stories.PartClassNames} />

### Keep mounted and the native top layer

`keepMounted` keeps the children mounted while the modal is closed (hidden and inert), so typed input and component state
survive a close and reopen. A kept-mounted modal has no exit animation.

`renderAs="dialog"` renders a native `<dialog>` opened with `showModal()`, so it sits in the browser's top layer above every
fixed layer. Focus containment, Escape, scroll lock and the shared layer stack work as in portal mode.

| Contract              | `portal` (default)                                         | `dialog`                                                                            |
| --------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Stacking              | `z-index` layer in a portal                                | Browser top layer                                                                   |
| Page behind           | Made `inert` by the package                                | Made inert by the browser                                                           |
| Backdrop              | A fixed element                                            | The native `::backdrop`                                                             |
| Exit                  | Animated                                                   | Immediate                                                                           |
| Closed by the browser | Not applicable                                             | The `close` and `cancel` events become `onClose`; refused while `busy`              |
| Nesting               | Opened over a native dialog, it renders inside that dialog | A portal `Modal` or `ConfirmDialog` opened from it lives inside it and stays usable |

A portal modal opened while a native modal dialog is open renders inside that dialog automatically (unless you pass
`container`), and the dialog itself is not made inert. Escape closes the inner layer first.

### Slots and props

`title`, `description`, `headerAction`, `footer` and the body (`children`) are slots. Rest props and `className` go to the
dialog element. Everything the person reads arrives through props; only the close button's accessible name has an English
default (`closeLabel`, or `labels.close` from [LufiaProvider](?path=/docs/components-utilities-lufiaprovider--docs)).

### Accessibility

Follows the WAI-ARIA APG [Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) pattern.

| Key / action          | Behaviour                                                                                          |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| Tab                   | Moves to the next tabbable element in the dialog; from the last one, wraps to the first.           |
| Shift+Tab             | Moves backwards; from the first (or the dialog itself), wraps to the last.                         |
| Escape                | Calls `onClose` (when `closeOnEscape`). Only the topmost of stacked dialogs reacts.                |
| Click on the backdrop | Calls `onClose` (when `closeOnOutsideClick`) if the press also began there.                        |
| Open                  | Focus moves to the dialog (named by its title). `initialFocus="first"` or a ref chooses otherwise. |
| Close                 | Focus returns to the element that opened it.                                                       |

- `role="dialog"` (or `alertdialog`), `aria-modal="true"`, `aria-labelledby` the title and `aria-describedby` the
  description when there is one.
- The page behind is made `inert` and page scroll is locked, so neither keyboard, pointer nor screen reader can reach it.
  The notification region of `ToastProvider` stays live.
- The dialog is the scroll container, with the header and footer sticky. Long content scrolls with the arrow keys while
  focus is on the dialog, with no extra tab stop.
- Close button: 36 px on desktop and 44 px on phones. Focus is always visible. Under `forced-colors` the border uses
  `CanvasText`.
- Motion uses `--lufia-motion-duration-enter` (240 ms) and `-exit` (160 ms), scale on desktop and rise on phones. Under
  `prefers-reduced-motion` it appears and disappears at once.
- Choose the initial focus deliberately. The default (the dialog) is safe for informational content; for a destructive
  prompt focus the safe action (`ConfirmDialog` does).

Not yet recorded: a manual VoiceOver and NVDA pass (required before `stable`).

### Do and don't

<ModalDoDont />

### When to use

- A focused task or a decision that must be finished or abandoned before returning to the page: editing a record, picking
  from a list, confirming settings.
- Anything that interrupts and needs an answer: build on it with [ConfirmDialog](?path=/docs/components-overlays-confirmdialog--docs).

### When not to use

- A message that does not need a response: use a [Toast](?path=/docs/components-feedback-toast--docs).
- Content the person should be able to compare with the page. A side panel or an inline expansion lets them keep the
  context a modal hides.
- Navigation. If the content has its own URL and is more than a step, make it a page. To make a modal linkable, drive
  `open` with `useModalState`.

### Content guidelines

Titles say what the dialog is for ("Edit project", "Delete invoice 2041?"), not "Are you sure?". Buttons say what they do
("Save changes"), not "OK". Put the primary action last and the cancel action before it; on phones the order reverses so the
primary action sits on top.
