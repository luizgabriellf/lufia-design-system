<Section id="overview">

A horizontal set of sibling views of one page, such as an overview and a work queue. Each item has a label and, optionally,
a description and an icon. An indicator slides to the chosen one.

<Canvas of={Stories.Links} />

### Usage

```tsx
import { PeerNav } from "@lufia/design-system/components/PeerNav";

<PeerNav
  label="Dashboard views"
  value="overview"
  items={[
    { key: "overview", label: "Overview", description: "Totals", icon: <GridIcon />, href: "/dashboard" },
    {
      key: "work",
      label: "Work",
      description: "Needs attention",
      icon: <InboxIcon />,
      href: "/dashboard/work",
    },
  ]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from your copy layer. Links render through
the `linkComponent` set on `LufiaProvider`, so client-side routing works.

### Links or tabs

The semantics depend on what the items are, and the component derives it so the markup cannot lie.

|                 | Every item has an `href`                  | Some item has no `href`                                |
| --------------- | ----------------------------------------- | ------------------------------------------------------ |
| Renders         | `<nav aria-label>` with one link per item | `role="tablist"` with one `role="tab"` button per item |
| Current item    | `aria-current="page"`                     | `aria-selected="true"`                                 |
| Use when        | Each view is its own URL                  | Each view swaps content on the same page               |
| Tab order       | Every link is a tab stop (native links)   | One tab stop; arrow keys move inside                   |
| State ownership | The page: `value` follows the route       | `value` or `defaultValue`, with `onValueChange`        |

A mix is not offered on purpose: a tablist promises arrow keys that links do not have. A tab can name its panel with
`controls`; give the panel `role="tabpanel"` and `aria-labelledby="<id>-tab-<key>"` (set `id` on `PeerNav`).

### Keyboard

| Key                | Links                    | Tabs                                           |
| ------------------ | ------------------------ | ---------------------------------------------- |
| Tab / Shift+Tab    | Moves between links      | Enters and leaves the tablist (one stop)       |
| Enter              | Follows the focused link | Selects the focused tab (it is a button)       |
| Left / Right arrow | Not used                 | Previous / next tab, wrapping; reversed in RTL |
| Home / End         | Not used                 | First / last tab                               |

Tabs use automatic activation: the arrow key focuses and selects, which suits views that render without a wait. Disabled
tabs are skipped.

### Accessibility

- Always give `label`: a page often has several navigations or tablists.
- Icons are decorative. The description is part of the link's or tab's name.
- A click on a link moves the indicator and the chosen styling at once, but `aria-current` stays on the page shown until
  the route changes. Modified clicks (open in new tab) change nothing.
- Five or more items scroll sideways instead of shrinking; the current one is brought into view and a fade marks the edge that
  hides more. On narrow screens the description is hidden and the icon moves above the label.
- Target height is at least 3rem. Focus shows a 2px ring. The indicator slide uses `transform` only and is a no-op under
  `prefers-reduced-motion`. In forced-colors mode the active item keeps a `Highlight` border.

<Section id="guidelines">

### When to use

- Two to six peer views of one screen that share a heading and data.

### When not to use

- Page-level site navigation (use the app shell), steps in order (use `Stepper`), or a switch between two display modes.

### Content guidelines

Labels are one or two words. Descriptions are a short phrase and may be omitted; they disappear on phones.
