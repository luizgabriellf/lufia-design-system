### Usage

```tsx
import { Button } from "@lufia/design-system/components/Button";

<Button variant="primary" iconStart={<PlusIcon />} onClick={create}>
  New report
</Button>
<Button href="/reports" iconEnd={<ArrowRightIcon />}>Open reports</Button>
```

Strings in the snippet are plain literals. In your app they arrive through props from your copy layer. With `href`, the link
renders through the `linkComponent` set on `LufiaProvider`, so client-side routing works.

### A link the provider cannot express

`href` is a string and goes through one link component. When a call to action needs more than that, such as a router link
with a route object or a locale, or a plain `<a>` that must skip the router, pass the element as `render`. It gets the
button's class, state, content and remaining props, and keeps its own props. Put `href` on the element.

```tsx
<Button
  variant="primary"
  render={<RouterLink href={{ pathname: "/reports", query: { year: "2026" } }} locale="en" />}
>
  Open reports
</Button>
```

The element must render one anchor or button and pass `className`, `data-*`, `aria-*`, `onClick` and `children` through to
it. `disabled` and `loading` mark it `aria-disabled` and ignore activation, as they do for `href`.

#### Server Components

A `render` element must be created in a Client Component. When a Server Component passes an element whose component
suspends on the server, it can reach the button as a lazy reference, and `Button` throws an error that says so. In
consuming apps, build the button inside a small client component and use that from the server instead (or pass a plain
`<a>`).

```tsx
"use client";

export function ReportsButton({ children }: { children: ReactNode }) {
  return (
    <Button variant="primary" render={<RouterLink href={{ pathname: "/reports" }} />}>
      {children}
    </Button>
  );
}
```

### Variants

| Variant     | Use for                                                       |
| ----------- | ------------------------------------------------------------- |
| `primary`   | The one main action of a view or dialog                       |
| `secondary` | The default; any other action                                 |
| `ghost`     | Low-emphasis actions, toolbars, actions repeated in lists     |
| `danger`    | Destructive actions that are about to happen (delete, remove) |
| `link`      | An action inside a sentence, or a quiet "show more"           |

### Link variant

`variant="link"` is text: the accent colour, no fill, border, shadow, padding or minimum height. It is `display:
inline-flex` on the text baseline and, when `size` is left out, inherits the font size of the text around it. The
underline appears on hover and on keyboard focus, next to the focus ring. It works with `iconStart`, `iconEnd`, `loading`,
`href` and `render` like any other variant.

It is inline text, so it keeps **no touch-target floor**: the 2.75rem minimum height that every other variant takes on
coarse pointers would break the line it sits in. Give a standalone action a real variant instead, and keep `link` for
words inside a sentence or a short "show more" under a list.

### Loading

`loading` keeps the label in the layout (hidden visually), draws a spinner on top and sets `aria-busy="true"`. The width
does not change. The button stays focusable and ignores activation instead of being disabled, so keyboard focus is not lost
when a submit starts. Announce the outcome in a live region or a toast; `aria-busy` alone is not announced.

### Themed surface

A theme can give buttons a richer surface through `--lufia-button-*` hooks, without a new prop: a fill (any `background`,
a gradient included), a border, a shadow and a hover lift. The fill and the border are separate hooks because a gradient
is not a valid border colour. The border defaults to transparent with the fill painted under it, so leave the border hook
unset for a border that matches the fill, and set it when you want a visible ring. The full table, with defaults, is in
Foundations / Theming components.

### Keyboard

| Key           | Action                                                |
| ------------- | ----------------------------------------------------- |
| Tab           | Moves focus to the button (a disabled one is skipped) |
| Enter / Space | Activates a button; Enter activates a link            |

### Accessibility

- Native elements, so role, focus and activation come from the browser.
- Focus shows a 2px ring with an offset in every variant. In forced-colors mode the border uses `ButtonText`.
- Icons are decorative and hidden; the label is the accessible name.
- Targets are at least 2rem tall (`sm`), and 2.75rem on coarse pointers. The `link` variant is the exception: it is inline text and has no minimum height.
- A link used as a button is marked `aria-disabled` when disabled or loading, and its activation is cancelled.
- The hover lift applies only where a pointer can hover and is dropped under `prefers-reduced-motion`; the press scale takes over while the button is held.
- The spinner is a rotation only and stops under `prefers-reduced-motion`; `aria-busy` and the cursor still say it is busy.

### Do and don't

<ButtonDoDont />

### When to use

- Anything that does something on the page: submit, open a dialog, add, save.
- With `href`, a call to action that navigates and should look like a button.

### When not to use

- Navigation inside text: use `Link`.
- A button with only an icon: use `IconButton`, which requires an accessible name.
- More than one `primary` in the same view.

### Content guidelines

Start with a verb ("Save changes", "Delete record"). Keep it to one to three words; longer labels wrap instead of
truncating. Give the destructive action a specific name rather than "Yes".
