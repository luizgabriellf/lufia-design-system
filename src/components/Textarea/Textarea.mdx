A multi-line text control with the same box as `TextInput`, vertical resizing and an optional character count.

<Canvas of={Stories.WithCount} />

### Usage

```tsx
import { FormField } from "@lufia/design-system/components/FormField";
import { Textarea } from "@lufia/design-system/components/Textarea";

<FormField label="Notes" hint="Visible to everyone on the project.">
  <Textarea name="notes" rows={5} maxLength={500} showCount />
</FormField>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use.

### Character count

`showCount` renders the count under the box, as `12 / 200` when `maxLength` is set. It is added to the control's
`aria-describedby`, so a screen reader reads it with the field's description when the control is focused. It is **not** a live
region while the person types, because that would read out every keystroke. In the last tenth of the limit, and past it, an
hidden status announces `formatCountAnnouncement(length, max)` and the visible count turns bold as well as amber.

`maxLength` stops typing at the limit. If you want people to exceed the limit and fix it, leave `maxLength` off and validate
yourself, showing the error in the `FormField`.

### Sizing the field

`className` goes on the box that draws the border; `rootClassName` goes on the root element that wraps the box and the
count. Size the field with the root: a width in a grid, or `flex: 0 0 12rem` in a row. The root already fills the space
left in a flex row (`flex: 1 1 auto; min-inline-size: 0`), so an `autoSize` field does not collapse next to a button.

<Canvas of={Stories.InFlexRow} />

### Auto height

`autoSize` makes the box grow with its content instead of scrolling. `rows` is the minimum height (it still defaults to 4,
so pass `rows={1}` or `rows={2}` for a compact start) and `maxRows` is the optional maximum, after which the box scrolls.
`maxRows` is never read as less than `rows`. The manual resize handle is removed in this mode.

Where the browser supports CSS `field-sizing: content`, the browser does the growing and the component runs no script for
it. Elsewhere a small fallback measures the content on every change, on a form reset and when the width changes, and sets
the height; the same minimum and maximum clamp it. It works controlled and uncontrolled. A value set on an uncontrolled
textarea from script (`node.value = ...`) fires no event, so the fallback does not see it: use a controlled textarea for that.

### Accessibility

| Key / action | Behaviour                                                                |
| ------------ | ------------------------------------------------------------------------ |
| Tab          | Moves focus in and out. Tab does not insert a tab character.             |
| Enter        | Inserts a new line. It never submits the form.                           |
| Typing       | Native. The count is updated but not announced until close to the limit. |

- The resize handle is vertical only, so the box cannot grow wider than its container at 320px.
- A read-only textarea inside a required `FormField` is not required: it gets no `required`, no `aria-required` and no mark.
- With `autoSize`, a box that reached `maxRows` scrolls inside and stays keyboard-scrollable like any textarea; the growing never moves focus or announces anything.
- Focus ring, forced-colors and invalid styling match `TextInput`.

</Section>

<Section id="guidelines">

### When to use

- Free text that may run past one line: notes, descriptions, messages.

### When not to use

- A short value: use `TextInput`. Do not stretch a textarea to look like an input.
- Formatted text. This is plain text only.

### Content guidelines

Say how much is expected in the hint ("A sentence or two is enough"). Show the count only when a limit exists or matters.
Phrase `formatCount` as what is left ("12 characters left") when the limit is tight.
