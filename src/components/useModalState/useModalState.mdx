# useModalState <StatusBadge status="beta" />

Keeps "which modal is open" in the URL, so a refresh or a shared link reopens it and the browser's back button closes it.
Router-agnostic: it talks to the URL through a small adapter.

<Canvas of={Stories.Default} />

## Usage

Without a router it uses the History API:

```tsx
import { useModalState } from "@lufia/design-system/components/useModalState";

const { modal, id, open, close } = useModalState();

<Modal open={modal === "detail"} onClose={close} title="Detail">
  ...
</Modal>;
```

With a router, pass an adapter. For Next.js:

```tsx
const searchParams = useSearchParams();
const router = useRouter();
const pathname = usePathname();

const adapter: ModalStateAdapter = {
  get: () => searchParams,
  set: (params, mode) => {
    const query = params.toString();
    router[mode === "push" ? "push" : "replace"](query ? `${pathname}?${query}` : pathname);
  },
};
const { modal, open, close } = useModalState({ adapter, onNavigate: startProgress });
```

| Option       | Notes                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------ |
| `adapter`    | `{ get, set, subscribe? }`. `get` is called on render and at each `open`/`close`.          |
| `keys`       | Rename `modal`, `id`, `returnModal`, `returnId` if they collide with the app's parameters. |
| `onNavigate` | Called just before the URL is written (for a progress bar, analytics).                     |

`open(name, id?, { consumeKeys })` drops the listed one-shot parameters (a `?new=1` deep link) so they do not reopen the
modal on refresh. Opening a modal from another records the parent; `close()` returns to it, or to a clean URL.

## When to use

- Modals people link to, refresh on, or expect the back button to close: record details, edit forms.

## When not to use

- Transient confirmations and menus. A confirmation should not survive a refresh; use `useConfirmDialog` or plain state.
- Anything that must not appear in the URL (personal data belongs in the `id`'s lookup, not in the address).

## Accessibility

- A refresh reopens the modal, and there is no opener to return focus to. Focus then goes back to the page body when it
  closes. If that matters, manage focus in the consumer.
- `open` pushes a history entry and `close` replaces it, so Back closes the modal and does not stack closed states.
- Opening and closing are real navigations: in a routed app, let `onNavigate` drive the same loading indication as
  other navigations.
