<Section id="overview">

A hook that locks page scroll while an overlay (modal, drawer, sheet) is open, and restores the scroll position when it
closes. Locks are reference counted, so stacked overlays are safe.

<Canvas of={Stories.DocumentScroll} />

### Usage

```tsx
import { useBodyScrollLock } from "@lufia/design-system/components/useBodyScrollLock";

function Modal({ open }: { open: boolean }) {
  useBodyScrollLock(open);
  // ...
}
```

Apps whose shell pins the layout to the viewport and scrolls an inner container should list those containers:

```tsx
useBodyScrollLock(open, { scrollContainerSelectors: [".app-content", ".page-scroller"] });
```

The first selector that matches an element that is overflowing and has a computed `overflow-y` of `auto` or `scroll`
is locked instead of the body. The allow-list is explicit on purpose, so a nested table is never locked by accident.

In document mode the width of the vanishing scrollbar is added to `body`'s right padding, so a page behind a modal does not
shift sideways on desktop. It is removed on release.

On release the scroll position comes back with `behavior: "instant"`, so a page or app that sets
`scroll-behavior: smooth` on `html` does not animate the jump back to where the person was.

`isBodyScrollLocked()` reports whether any lock is held, for code outside the overlay's tree.

### Notes

Client-only (`"use client"`). In document mode `body` becomes `position: fixed`; avoid reading `window.scrollY` while
locked.

</Section>

<Section id="accessibility">

### Accessibility

- Locking scroll does not move focus or trap it. Pair it with a focus trap and `aria-modal` on the dialog.
- The previous scroll position is restored on release, so keyboard and screen-reader users return to where they were.
- It only touches inline styles (`overflow`, `position`, `top`, `width`, `padding-right`, `overscroll-behavior`) and removes them on cleanup,
  including on unmount.
