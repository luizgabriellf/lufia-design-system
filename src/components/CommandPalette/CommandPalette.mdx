A search-and-run overlay opened with Ctrl+K or Cmd+K: type to filter navigation targets and actions, choose with the
arrow keys, run with Enter.

<Canvas of={Stories.OpenOnLoad} />

### Usage

```tsx
import { CommandPalette } from "@lufia/design-system/components/CommandPalette";

<CommandPalette
  open={open}
  onOpenChange={setOpen}
  items={[
    { key: "new", label: "New document", group: "Actions", icon: <PlusIcon />, onSelect: createDocument },
    {
      key: "settings",
      label: "Settings",
      group: "Go to",
      keywords: "preferences",
      onSelect: () => router.push("/settings"),
    },
  ]}
  labels={{
    title: "Search or run a command",
    placeholder: "Type a command or search…",
    empty: (query) => `No results for “${query}”`,
    resultCount: (count) => `${count} results`,
  }}
  hint="Search by name, or choose an action."
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from your copy layer, so word order and
plurals are yours. The commands are data and the palette knows no routes: `onSelect` does the work (navigate, open a
modal). The `AppShell` `search` entry is the natural trigger: `search={{ label, onSelect: () => setOpen(true) }}`.

#### Filtering

The default matcher (`filterCommands`, exported) requires every word of the query to appear in the label, description, group
or keywords, ignoring case and accents. Pass `filter` to replace it. For a server search, pass `filter={() => true}`, listen
to `onQueryChange` and feed the answer back through `items`. A command with `keepOpen` leaves the palette open after it
runs, for commands that show their answer inside.

### Sections, answers and Escape

- `groupOrder` fixes the order of the section headings; other groups follow in order of first use.
- `bodyOverride` replaces the results with your own content (an answer to the query). While it is set the field is not a
  listbox and the arrow keys and Enter do nothing. A function gets `{ query }`.
- `onEscape` runs before Escape closes the palette. Return `true` after leaving a sub-mode (clearing the answer) and the
  palette stays open; the next Escape closes it.
- `loading` marks the results `aria-busy` and holds the empty message back until a server search answers. Pair it with
  `onQueryChange` and `filter={() => true}`.

### Keyboard and accessibility

It follows the WAI-ARIA APG pattern for a combobox with a listbox popup, inside a modal dialog.

| Key          | Action                                                                   |
| ------------ | ------------------------------------------------------------------------ |
| Ctrl/Cmd + K | Opens the palette; closes it when open (`shortcut={false}` turns it off) |
| Type         | Filters; the first match is highlighted                                  |
| Down / Up    | Moves the highlight, wrapping at the ends                                |
| Enter        | Runs the highlighted command                                             |
| Escape       | Closes; focus returns to where it was                                    |
| Tab          | Cycles between the field and the close button                            |

- The text field is the `combobox`. Focus never leaves it: the highlighted option is named by `aria-activedescendant`, and
  options are not focusable, as the pattern requires. `aria-expanded` is false when nothing matches.
- Groups are `role="group"` named by their heading. A polite status line announces the result count as you type.
- The highlight has a fill and a bar on the inline-start edge, not colour alone; hover moves it too.
- The dialog is modal: focus is trapped, the page behind is inert and its scroll is not moved. Escape handling belongs to
  `useFocusTrap`, so nested overlays close one at a time. The palette adds no outside-click listener of its own; a tap on the
  dimmed page closes it.
- It rises and fades with the `--lufia-motion-*` tokens and appears at once under `prefers-reduced-motion`.

<Section id="guidelines">

### When to use

- Apps with many destinations and actions, where power users want the keyboard.

### When not to use

- As the only way to reach something: every command should also exist in the visible UI.

### Content guidelines

Command labels are verbs for actions ("New document") and nouns for destinations ("Settings"). Use `keywords` for the words
people might type that the label does not contain.
