A searchable single select. The person types to narrow a list and picks one option. Options can arrive asynchronously, and
the empty and loading states are part of the component.

<Canvas of={Stories.Open} />

### Anatomy

<ComboboxAnatomy />

### Usage

```tsx
import { FormField } from "@lufia/design-system/components/FormField";
import { Combobox } from "@lufia/design-system/components/Combobox";

<FormField label="City" error={errors.city}>
  <Combobox
    name="city"
    options={cities}
    placeholder="Search for a city"
    emptyLabel="No city matches that search."
    loadingLabel="Loading cities…"
    onValueChange={(value) => setCity(value)}
  />
</FormField>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use.
`emptyLabel` and `loadingLabel` are required because a list without them fails silently. Each option has a `value`, a `label`
and optionally a `description` and `disabled`. With `name`, the chosen **value** is submitted (not the text).

### Filtering

By default the label must contain the typed text, ignoring case and diacritics ("sao" finds "São Paulo"), and options keep
the order you gave them. Typing highlights the first enabled match, so Enter picks it. Pass `filter={(option, query) => boolean}`
to match another way, or `filter={false}` to show `options` as given.

`maxResults` caps a long local list at its first matches, applied after the filter; typing narrows it. `resultsLabel` then
gets both the number shown and the number that matched (`(count, total) => string`), so the announcement can say how many
more there are.

### Async options

Listen to `onQueryChange`, set `loading` while you fetch, and replace `options` when results arrive. Use `filter={false}` so the
component trusts the list it is given. The label of the chosen option is remembered even when a later search replaces it; for
a value set before any options loaded, pass `valueLabel`. `onQueryChange` also fires with `""` after a choice or a clear, so
you can reset the list.

<Canvas of={Stories.AsyncOptions} />

### Free text

Set `freeText` when the person may submit something that is not listed. The value is the typed text, trimmed (`null` when
empty or whitespace only), and `onValueChange` reports it with `null` as the option. It follows every keystroke, so a button
that waits on the value is enabled as soon as there is text. Enter, Tab, Escape, the toggle button and blur settle the text.
Enter keeps what was typed, closes the list and does not submit the form, and it never picks the first match. Typed text is
never matched to an option, even when it equals an option's `value` (an id such as "12" stays "12"), and it wins over
`valueLabel`. Choosing an option sets its `value`; a `value` set by the parent resolves to its option as usual. Native attributes such as `maxLength` go to the input.

<Canvas of={Stories.FreeText} />

### Long chosen labels

By default the chosen label stays on one line and is cut with an ellipsis. Set `wrapValue` and a long label wraps onto up to
`maxValueLines` lines (default 2) while the list is closed, so it stays readable on a narrow screen; the box grows with it and
the clear and toggle buttons stay level with the first line. Opening the list or typing returns the box to one editable line.
The wrapped text is a visual layer over the real input, which keeps the accessible name, the value and the keyboard.

### Inside a dialog

The list is dismissed through the package's layer stack (`useDismiss`), the same one `Modal` uses, so only the topmost layer
reacts to Escape and to an outside press. Escape closes the list; the next Escape closes the dialog. The component adds no
document listeners of its own.

### Accessibility

Follows the WAI-ARIA APG [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) pattern with a listbox popup and
list autocomplete: `role="combobox"` on the input with `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` and
`aria-activedescendant`. DOM focus stays in the input; the highlight is virtual.

| Key / action    | Behaviour                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------ |
| Typing          | Opens the list and narrows it by the text. The first enabled match is highlighted.               |
| Down arrow      | Closed: opens on the chosen option, or the first. Open: next enabled option, wrapping.           |
| Up arrow        | Closed: opens on the chosen option, or the last. Open: previous enabled option, wrapping.        |
| Enter           | Chooses the highlighted option, closes the list and does not submit the form. With none, native. |
| Escape          | Open: closes the list and restores the chosen text. Closed and `clearable`: clears the choice.   |
| Tab             | Closes the list without choosing; focus moves on.                                                |
| Home / End      | Move the caret in the text, as in any text field.                                                |
| Click an option | Chooses it. Focus stays in the input. A disabled option ignores the click.                       |
| Click the box   | Opens the list and selects the text, so typing replaces it.                                      |

- Option ids come from their `value` and do not change between renders, so assistive technology keeps its place when the list updates.
- A visually hidden status region announces the empty and loading texts, and the result count when you pass `resultsLabel`.
- A list that is empty or loading is not "expanded": there is nothing to point `aria-controls` at, so the message lives in the status region only.
- The highlighted option is shown with a fill and a bar on its start edge, and in forced-colors with the system highlight.
- A `required` combobox is invalid until an option is chosen, whatever text is typed: the browser refuses to submit, focuses the box and shows its own message (or `requiredMessage`). It also carries `aria-required`.
- A form `reset` returns it to `defaultValue`.
- It opens upward when there is little room below the box. Room is measured against the viewport and every ancestor that clips vertically (a scrollable dialog body, a table cell), taking the room they all leave, and the list is shortened to the room that is left (never under about six rem). The measure is repeated, once per frame, while the page or any container scrolls and when the window is resized; scrolling does not close the list. The list is placed inside the field and is not portaled, so a clipping parent still bounds it. A portaled list is planned as a follow-up.
- Given an `id`, the input keeps it, the list is `<id>-listbox` and each option is `<id>-option-<encoded value>`: any character of the value outside `A-Za-z0-9-` is written as `_<hex code point>_`.

Not yet recorded: a manual VoiceOver and NVDA pass (required before `stable`). Combobox is the component most likely to behave
differently across screen readers.

<Section id="guidelines">

### When to use

- A list too long to scan (more than about fifteen options), or one where people know what they are looking for.
- Data that is loaded as the person types.

### When not to use

- A short list: use `Select` (native, with the platform's picker on phones) or `RadioGroup`.
- A plain text field: use `TextInput`. Without `freeText` the box only accepts a listed option.
- Several choices at once: this is a single select.
- A search that opens a results page: use `SearchInput`.

### Content guidelines

Labels are the thing being chosen ("City", "Assignee"), the placeholder says how ("Search for a city"). The empty text says
what to do next ("No city matches that search. Try another name."), and the loading text names what loads. Keep option labels
short and put the secondary detail (country, e-mail, code) in the description. Do not include the description in what must be
unique to tell options apart.
