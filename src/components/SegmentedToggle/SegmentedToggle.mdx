Two to four compact choices in one bordered group, where one is chosen (always, unless `value` is `null`). An indicator slides behind the chosen
segment.

<Canvas of={Stories.Default} />

### Usage

```tsx
import { SegmentedToggle } from "@lufia/design-system/components/SegmentedToggle";

<SegmentedToggle
  label="View"
  value={view}
  onValueChange={setView}
  options={[
    { value: "list", label: "List" },
    { value: "board", label: "Board" },
  ]}
/>;
```

Strings in the snippet are plain literals. In your app they arrive through props from whatever copy or i18n layer you use.
With `name`, the chosen value is submitted with the form.

### Status picker

A per-row picker where a fresh row has no status. `value={null}` (controlled) means nothing is chosen: no segment is checked and
the indicator is hidden; it appears, without sliding in from elsewhere, when a segment is first chosen. `tone` colours the
chosen segment with the status tokens, `size="sm"` fits dense rows and `allowDeselect` clears the choice when the chosen
segment is activated again.

<Canvas of={Stories.StatusPicker} />

```tsx
<SegmentedToggle
  label="Status"
  size="sm"
  allowDeselect
  value={status} // string | null
  onValueChange={setStatus} // (value: string | null) => void, because of allowDeselect
  options={[
    { value: "pass", label: "Pass", tone: "success" },
    { value: "fail", label: "Fail", tone: "danger" },
    { value: "na", label: "N/A", tone: "neutral" },
  ]}
/>
```

`onValueChange` receives a `string`, and also `null` only when `allowDeselect` is set (the prop types are a union on
`allowDeselect`), so existing handlers typed `(value: string) => void` keep compiling. With `name`, nothing is submitted while
the value is `null`.

### Form events

When the user chooses a segment (a click or an arrow key), a bubbling `input` Event and then a bubbling `change` Event are dispatched from the hidden input (from the group itself when there is no `name`), after the new value is in the DOM. A native listener on the `<form>` (`form.addEventListener("change", …)`) or a React `onInput` can tell that the user edited it, as with native radios. A React `onChange` on the form does not fire: React ignores hidden inputs for `onChange`, so use `onInput` there. Nothing is dispatched for a `value` that the parent sets, for a form reset, or for choosing what is already chosen. The event waits for the commit that shows the new value, so a controlled parent may accept it later (a transition works too). One edge: if the parent refuses the choice and keeps showing the old value, then later sets that same value, that one change is announced.

A form reset restores the `defaultValue` of the latest render, as native fields do, including when a form action has just changed it.

### Accessibility

Follows the WAI-ARIA APG [Radio Group](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) pattern with a visual treatment of
segments. It is a radiogroup and not a tablist because it chooses a value and does not control panels.

| Key / action       | Behaviour                                                                                |
| ------------------ | ---------------------------------------------------------------------------------------- |
| Tab / Shift+Tab    | Enters the group at the chosen segment (the first enabled one when none is); leaves it.  |
| Right / Down arrow | Moves to the next enabled segment and chooses it. Wraps. Reversed in RTL for Left/Right. |
| Left / Up arrow    | Moves to the previous enabled segment and chooses it. Wraps.                             |
| Space / click      | Chooses the focused segment; with `allowDeselect`, clears it when already chosen.        |

- `label` names the group and is required. Icons are decorative.
- The indicator animates `transform` only, jumps on resize, and does not animate under `prefers-reduced-motion`.
- Before scripts run the chosen segment paints its own border and fill, so the choice is visible without the indicator.
- Under `forced-colors` the chosen segment keeps a `Highlight` border.
- Selection follows focus: an arrow key moves focus and chooses, also when nothing was chosen. Space or a click on a focused segment chooses it.
- `tone` is never the only cue: the chosen segment also has the selected border and the indicator. Text and fill pairs are the status `fg` on `bg` pairs checked by `npm run contrast`.

<Section id="guidelines">

### When to use

- Switching how the same content is shown or sourced: list or board, upload or link, monthly or yearly.

### When not to use

- Moving between pages or sibling views with their own content: use `PeerNav` (links or tabs).
- On and off: use `Switch`.
- More than four options, or long labels: use `RadioGroup` or `Select`.

### Content guidelines

Labels are one or two words and parallel ("List", "Board"). They name what is shown, not the action. The group `label` names
the dimension being chosen ("View", "Billing period").
