<Section id="overview">

Page navigation for a list or table: previous and next, numbered pages that collapse into an ellipsis, and a status line.
It is the view for `usePagination`.

<Canvas of={Stories.WithUsePagination} />

### Usage

```tsx
import { Pagination } from "@lufia/design-system/components/Pagination";
import { usePagination } from "@lufia/design-system/components/usePagination";

const { slice, page, totalPages, total, setPage } = usePagination(rows, 10);

<Pagination
  page={page}
  totalPages={totalPages}
  total={total}
  onPageChange={setPage}
  labels={{
    nav: "Results",
    previous: "Previous",
    next: "Next",
    page: (n) => `Page ${n}`,
    summary: (n, count, all) => `Page ${n} of ${count}, ${all} results`,
  }}
/>;
```

Every string, including the status line, arrives through `labels` (functions, so word order and plurals are yours). Hide
the component when everything fits on one page (`usePagination` returns `show`).

For server-side pagination or crawlable pages, pass `hrefFor` and the controls become real links rendered through the
configured `linkComponent`.

### Compact variant and your own buttons

`variant="compact"` renders previous and next only, with the status line at every width. `buttonClassName` puts your own
class on every control and leaves out the built-in control look, for an app that already has a button style.

### Icons on previous and next

`previousIcon` and `nextIcon` add an icon inside the control, before the previous text and after the next text. The icon is
hidden from assistive technology and does not shrink; the visible text stays the accessible name. Nothing is wired in by
default: pass the package's chevron or arrow icons. Following the convention used by other directional icons, the icon is
mirrored in CSS in right-to-left text, so pass a left-pointing icon for previous and a right-pointing one for next, as you
would in left-to-right text, and do not flip them yourself.

<Canvas of={Stories.WithIcons} />

### Open-ended lists

When the source only says whether another page exists (a cursor or a "load one more than the page size" check), omit
`totalPages` and pass `hasNext`. No numbered pages or ellipsis are rendered (the same structure as `variant="compact"`),
previous is available after page 1 and next while `hasNext` is true. The status line comes from `labels.position`, and
falls back to `labels.page`; `labels.summary` is not called. When `totalPages` is given, `hasNext` is ignored.

`totalPages` stays an optional prop with this contract rather than a discriminated union, so every existing call keeps
compiling and inferring as before.

<Canvas of={Stories.OpenEnded} />

### Native disabled

By default an unavailable previous or next control is `aria-disabled`: it stays focusable so focus is not lost when the last
page is reached. `disabledMode="native"` renders a real `disabled` attribute instead, for apps whose styles and tests rely on
`:disabled`. The control then leaves the tab order. Links (`hrefFor`) always use `aria-disabled`.

### Keyboard and accessibility

| Key                          | Action                                            |
| ---------------------------- | ------------------------------------------------- |
| Tab / Shift+Tab              | Moves between previous, the page numbers and next |
| Enter (and Space on buttons) | Goes to the focused page                          |

- A `<nav>` landmark named by `labels.nav` holds a list. The current page has `aria-current="page"`, and its button does
  nothing when pressed.
- Page buttons are named "Page 3" while showing "3"; the visible text is part of the name.
- Previous and next at the ends use `aria-disabled` instead of `disabled`, so focus is not dropped when you reach the last
  page by pressing next. They ignore clicks.
- The status line is a polite live region that announces the new page; on phones it is the only place the position shows,
  because the numbers are hidden when the component itself is narrower than 40rem (a container query, so it also holds in a side panel).
- Controls are 2.5rem square. Focus shows a 2px ring; the current page also has a border and weight, not colour alone, and
  keeps a `Highlight` border in forced-colors mode.

<Section id="guidelines">

### When to use

- Long lists or tables that are paged. Prefer it to infinite scroll when people need to return to a position.

### When not to use

- Fewer than two pages, or feeds without a known end.

### Content guidelines

Keep the status line short and say what is paged: "Page 3 of 12, 118 results".
