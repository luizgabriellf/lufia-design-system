The semantic tokens (`--lufia-color-*`, `--lufia-font-*`) restyle the whole system. When a product needs more than a new
palette, such as a wider eyebrow tracking or a heavier card shadow, the components named below expose a **component
token**: a custom property that overrides one decision in one component.

## How it works

- A component reads `var(--lufia-<component>-<part>, <default>)`. The default is the value the component always had, so
  nothing changes until you set the property.
- The tokens are **not** declared by the package. Set them on `:root`, on your theme selector, or on any ancestor of the
  component, so the cascade does what you expect (a section of the page can differ from the rest).
- Prefer pointing them at semantic tokens (`var(--lufia-color-text-accent)`) so they follow light, dark and brand
  themes. A literal value is fine for sizes and tracking.
- Sizes and spacing are in `rem`, tracking in `em`.

## An example theme

```css
:root {
  /* Eyebrows: accent colour, wide tracking, a leading dash */
  --lufia-page-header-eyebrow-color: var(--lufia-color-text-accent);
  --lufia-page-header-eyebrow-tracking: 0.16em;
  --lufia-page-header-eyebrow-dash-size: 1.5rem;
  --lufia-page-header-eyebrow-dash-gap: 0.5rem;
  --lufia-page-header-title-tracking: -0.02em;

  /* Stat tiles: quieter label, bigger figure */
  --lufia-stat-tile-label-tracking: 0.14em;
  --lufia-stat-tile-value-size: 2.5rem;

  /* Cards: roomier, ruled header, deeper shadow */
  --lufia-card-header-padding: 1rem 1.5rem;
  --lufia-card-body-padding: 1.5rem;
  --lufia-card-shadow: var(--lufia-shadow-lg);

  /* Attention lists: slightly thicker bar */
  --lufia-attention-list-bar-width: 0.3125rem;
}
```

```tsx
<Card title="Needs attention" divider flush>
  <AttentionList barStyle="inset" items={items} aria-label="Needs attention" />
</Card>
```

## Rules for adding a component token

1. Name it `--lufia-<component>-<part>-<property>`, in kebab case. Document it here and in the component's page.
2. The fallback is the value the component used before, so adding a token is never a visual change.
3. Point colour tokens at semantic tokens by default; never at primitives.
4. A new token is a minor release. Renaming or removing one is breaking.
