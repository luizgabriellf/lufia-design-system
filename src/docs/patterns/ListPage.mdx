## Why it is built this way

- **Three levels of navigation, each with one job.** `PageHeader` says where you are, `PeerNav` switches between sibling views and `TableToolbar` narrows what you see inside one.
- **Changing a filter returns to page 1.** Staying on page 4 of a result set that now has two pages is the most common list bug.
- **The empty state offers the way out.** After a search or filter it says so and gives a single action that clears them.
- **Pagination announces itself.** The summary line ("Page 2 of 5, 23 results") is a polite live region, so a screen reader hears the change.
